# Publishing this mod

The standing process for every Teb Gen1Recomp mod. The engine's own guide
is the authority: https://github.com/bryanthaboi/gen1recomp/wiki/Guide-Publishing

## The surfaces, in order

1. **The private remote** (`origin`) — every commit, full history, semver
   tags. This is the source of truth and needs no approval.
2. **GitHub** (`tebwritescode/<repo>`) — on Teb's explicit go, per artifact.
   New repos go up as a single squashed commit; established repos keep
   their public history.
3. **Personal index** (`tebwritescode/gen1recomp-mods`) — the launcher's
   Find Mods feed for Teb's mods.
4. **Official index** (`bryanthaboi/gen1recomp-mod-index`) — one PR per
   mod; version bumps flow from GitHub releases automatically afterward.

## Releases come from CI, never by hand

`.github/workflows/release.yml` (generated by
`python tools/modkit.py add-release-workflow <id>` in the engine repo) is
the only thing that builds release assets. It publishes
**`<id>-<version>.zip` with the mod's files at the archive root** — the
shape Import mod .zip, Update and Versions install — plus sha256sums.

To cut a release: bump `manifest.json`'s version, push `main`. The
workflow resolves the version from the manifest and refuses to clobber
existing tags. Commits touching only `.github/**` or `**.md` do not
trigger it, so docs and workflow maintenance are always safe to push.


## Release notes

`release.yml` opens every release's notes with the manifest `description`,
so the launcher's version screens always say what the mod is before what
changed. Keep the description current — it is the first thing a player
reads on every version.

## The checklist before any release

- [ ] `manifest.json`: semver bumped, `"github": "tebwritescode/<repo>"` set
- [ ] `CHANGELOG.md` heading matches the manifest version
- [ ] From the **engine repo root** (paths are engine-relative — packing
      from the mod repo silently does nothing):
      `python tools/modkit.py validate mods/<id> --strict --base imported`
      and `python tools/modkit.py lint mods/<id>`
- [ ] Test suites green (unit + end-to-end drivers where the mod has them)
- [ ] PII scan of anything new: pseudonymous identity only, no LAN/tailnet
      addresses, no internal hostnames
- [ ] After CI: **download the built zip and open it** — `manifest.json`
      at the archive root, version matching. Verify the artifact, not the
      intent.

## Keeping the indexes current

- Personal index: add or touch `mods/tebwritescode@<id>/` (meta.json,
  description.md, thumbnail.png), run
  `GITHUB_TOKEN=$(gh auth token) node scripts/build.mjs --releases`,
  copy `site/data/` over `docs/data/`, push.
- Official index: `meta.json` mirrors the manifest (id, api, profile,
  permissions, conflicts); `node scripts/validate.mjs mods/tebwritescode@<id>`
  before the PR. Listed mods update from releases — tag, do not PR bumps.

## Special layouts

A repo that keeps the mod in a subdirectory (savesync uses `mod/`, with
`server/` and `tools/` beside it) patches two lines of the generated
workflow: `git archive HEAD:mod` in the build step, and
`mod/manifest.json` in the version step.
